# Day 7 — 1,200 req/s 기준 측정 (2026-11-05)

## 목적 및 실행 조건

1,200 req/s를 4분 동안 전달했을 때 요청 성공 여부와 실제 DB 저장 증가량을 확인한다. k6를 직접 실행한 결과로, DB·k6 CPU 수집 스크립트는 이번 실행에 사용하지 않았다.

- 명령: `RATE=1200 DURATION=4m k6 run load-test/telemetry.js`
- 대상: 로컬 `POST /api/v1/telemetry`, 차량 ID 11~60
- 부하 방식: `constant-arrival-rate`
- 사전 할당 VU / 실행 출력의 최대 VU: 100 / 100
- 환경·절차: [기존 baseline 문서](2026-11-04-k6-baseline.md#재측정-환경) 참조
- 정확한 실행 시작·종료 시각: 미기록. 아래 DB 조회 시각과 구분한다.
- 측정 직전 커밋·미커밋 변경, 예열·대기 절차 준수 여부: 이번 실행에서 별도 확인 기록 없음

## k6 결과

사용자가 제공한 콘솔 출력을 기준으로 기록했다. 이번 실행의 요약 JSON·CPU CSV·종료 코드 파일은 이 문서에 연결된 자료로 확보되지 않았다.

| 항목 | 결과 |
|---|---:|
| 실행 시간 | 4분 |
| 실제 요청률 | 1,199.988537 req/s |
| 요청 / 성공 체크 | 288,001 / 288,001 |
| HTTP 실패 / 체크 실패 | 0 / 0 |
| 완료 / 중단된 반복 | 288,001 / 0 |
| 응답 시간 평균 / 중앙값 | 1.30 / 1.21 ms |
| 응답 시간 p95 / p99 | 1.79 / 2.89 ms |
| 최대 응답 시간 | 26.93 ms |
| 실행 중 VU 범위 | 1~9 |

제공된 출력에 VU 한도 경고와 반복 누락은 보고되지 않았다. `dropped_iterations` 수치 자체는 출력에 없으므로 보고되지 않았다는 사실로 기록한다.

## DB 저장 건수 대조

기존 기록의 UTC(`+00:00`) 조회 시각을 KST(`+09:00`)로 변환했다. 아래는 DB 조회 시각이며 실제 부하 시작·종료 시각은 아니다.

| 시점 | 조회 시각(KST) | 전체 행 수 | 대상 차량 행 수 | 저장 성공 누적 | 저장 실패 누적 |
| --- | --- | ---: | ---: | ---: | ---: |
| 예열 전 | 2026-11-05 16:14:00.691867 +09:00 | 1,172,029 | 1,170,621 | — | — |
| 본 측정 직전 | 2026-11-05 16:21:59.719224 +09:00 | 1,178,035 | 1,176,627 | 미기록 | 0 |
| 본 측정 종료 후 | 2026-11-05 16:28:53.825568 +09:00 | 1,466,036 | 1,464,628 | 294,007 | 0 |
| 종료 후 − 본 측정 직전 | — | 288,001 | 288,001 | 확인 불가 | 0 |

- 전체 행 증가량: `1,466,036 - 1,178,035 = 288,001`
- 대상 차량 행 증가량: `1,464,628 - 1,176,627 = 288,001`
- 두 증가량 모두 k6 성공 체크 288,001건과 일치한다. 대상 외 차량 행 수는 직전·종료 후 모두 1,408건이다.
- 예열 전부터 본 측정 직전까지 전체·대상 차량 행 수는 각각 6,006건 증가했다. 이 값은 본 측정 건수에서 제외했다.
- 본 측정 직전 저장 성공 카운터는 미기록이다. 종료 누적값만으로 증가량을 확정하지 않으며, 직전 값을 역산해 관측값으로 채우지 않는다.

## Grafana 관측

제공된 화면의 약 16:24~16:29 KST 표시 구간 기준이다. 전체 4분 실행을 포함하는 고정 조회 링크는 아직 기록되지 않았다.

- 표시된 API 5xx 오류율과 HikariCP 대기 스레드는 0이었다.
- 부하 구간의 HikariCP 사용 중 커넥션은 대체로 1~2개, 유휴 커넥션은 8~9개였다.
- 서버 p95는 약 1.7 ms, p99는 약 2.6~2.9 ms였다. 이동 구간 히스토그램 추정값으로 k6 전체 실행 백분위와 구분한다.
- JVM CPU는 시계열이 표시됐고 낮은 사용률로 보였다. 정확한 평균·최댓값은 원시 지표를 조회하지 않아 확정하지 않는다.
- 저장 패널은 성공 누적 294,007건, 실패 누적 0건을 표시했다. 성공 숫자의 빨간색만으로 오류를 판단하지 않는다.

## 결론과 한계

이번 실행에서 약 1,200 req/s를 4분 동안 전달했고 288,001건 모두 HTTP·체크에 성공했다. 실제 DB 전체 및 대상 차량 행 증가량이 각각 288,001건으로 일치해 저장 건수 대조를 완료했다. 제공된 출력에서 이전 반복 누락은 보고되지 않았다.

저장 성공 카운터의 직전 값이 없어 k6·카운터·DB의 세 가지 값 전체 대조는 미완료다. DB·k6 CPU 기록도 없어 서버·DB·부하 발생기의 자원 상태를 함께 비교하거나 병목 위치를 판단할 수 없다. 최대 처리량·장시간 안정성·개별 데이터 내용까지 검증한 결과는 아니다.
