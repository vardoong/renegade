## 유휴 상태와 Simulator 실행 상태 비교

아래 값은 제공된 Grafana 스냅샷을 육안으로 확인한 근삿값이다. 동일 길이의 비교 구간을 별도로 지정한 정량 분석은 수행하지 않았다.

| 지표 | 실행 전 유휴 구간 | Simulator 실행 구간 |
|---|---|---|
| 텔레메트리 요청량 | 0 req/s | 약 1 req/s 유지 |
| JVM 스레드 수 | 약 29개 | 약 29개 유지 |
| JVM 힙 메모리 | 대략 60~100 MiB, GC 후 약 40 MiB로 감소 | 대략 40~85 MiB 범위에서 변동 |
| DB 활성 / 유휴 커넥션 | 수집 시점 기준 0 / 10개 | 수집 시점 기준 0 / 10개 |
| DB 커넥션 대기 스레드 | 0개 | 0개 |

| 텔레메트리 p99 | 요청 없음으로 계산 불가 | 초반 약 80ms대, 이후 대략 10~22ms |

p95·p99는 히스토그램 기반의 구간별 추정값이다. 표의 범위는 그래프에 표시된 값의 대략적인 범위이며, 실행 전체 요청을 합산해 계산한 p95·p99가 아니다.

DB 커넥션 지표는 15초 간격의 순간값이다. 요청 처리 중 커넥션 사용 시간이 짧으면 활성 상태가 수집되지 않을 수 있으므로, 활성 0개를 DB 미사용으로 해석하지 않는다.

## 관찰 및 해석

- Simulator 실행 구간에 텔레메트리 POST 요청량이 증가하고, 종료 후 감소하는 것을 확인했다.
- 저장 성공 카운터가 증가하고 추가 롤백이 없어 데이터 유입과 저장 결과 집계가 동작함을 확인했다.
- 힙 메모리는 증가 후 회수되는 패턴을 보였으며 GC 활동도 관측됐다. GC 시점의 영향을 받으므로 특정 시점의 메모리 값만으로 사용량 증가나 누수를 판단하지 않는다.
- 실행 초반 p99가 높았다가 낮아졌다. 초기화·워밍업 등의 원인 가능성은 있으나, 별도 분석을 하지 않아 원인은 확정하지 않았다.
- 관측한 구간에서 커넥션 대기는 없었다. 차량 1대 조건의 결과이며, 시스템 최대 처리량이나 고부하 안정성을 입증하는 결과는 아니다.
